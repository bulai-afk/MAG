# ADR-001: Модульный монолит

- Статус: принято
- Дата: 2026-09-09
- Этап: 1 — Bootstrap
- Связанные документы: [`docs/PROJECT_PLAN.md`](../PROJECT_PLAN.md) §8.3, §10

## Контекст

MAG — один продукт с одним основным сценарием: CSV → KPI → отчёт → PDF. На этапе 1 нет доказанного масштаба нагрузки, нет отдельной команды на каждый bounded context и нет требования независимого деплоя импорта, AI и публикации.

Микросервисы и Kubernetes дали бы независимый scale и изоляцию сбоев ценой распределённых транзакций, отдельного CI для каждого сервиса и более сложного локального запуска. Для команды из одного разработчика это замедлит проверку гипотезы.

При этом бизнес-правила нельзя складывать в Route Handlers и UI-компоненты: tenant isolation, расчёт KPI и публикация snapshot должны оставаться тестируемыми без HTTP.

## Решение

Первый релиз — **модульный монолит** в одном репозитории и одном деплое веб-приложения плюс один worker-процесс.

- `apps/web` — Next.js UI и BFF. Не обращается к ORM напрямую.
- `apps/worker` — фоновые jobs (CSV, AI, PDF, email) через Redis/BullMQ.
- `packages/*` — границы домена и инфраструктуры: `domain`, `csv`, `db`, `ai`, `email`, `ui`, `config`, `observability`.
- Локально PostgreSQL и Redis поднимаются Docker Compose, не кластером.
- Один pipeline CI на monorepo.

Не делаем: отдельные сервисы на каждый модуль, service mesh, Kubernetes, синхронные RPC между «сервисами».

## Последствия

Положительные:

- один clone и один набор команд `dev` / `typecheck` / `lint` / `test` / `build`;
- транзакции PostgreSQL остаются локальными;
- проще соблюдать правила из плана: Route Handler → application service → repository с `agencyId`;
- worker масштабируется отдельно от web без разрезания домена.

Отрицательные и ограничения:

- деплой web и worker связан по версиям пакетов;
- ошибка в одном модуле может уронить процесс, поэтому нужны health checks и ограниченный blast radius на уровне очереди, а не сети;
- выделение сервиса позже потребует стабильных application API внутри packages.

Пересмотр ADR, если появится отдельная команда на импорт, независимый SLA worker или нагрузка, которую вертикально не закрывает один процесс worker.

## Не в scope этого ADR

Выбор ORM, AI-провайдера, object storage и стратегии tenant isolation фиксируются отдельными ADR, когда дойдёт соответствующий этап.
