# Чат 04 — CSV import pipeline

Ты работаешь только над этапом 4 MAG. Прочитай CSV-контракт, модель imports, фоновые задачи и upload security в `docs/PROJECT_PLAN.md`. Используй только обезличенные fixtures этапа 0.

## Входное условие

Auth, agency/client tenancy и worker infrastructure работают и покрыты тестами.

## Цель

Надёжно превращать пользовательский CSV в канонические метрики с понятными ошибками и без дублей.

## Выполни

1. Создай schema и миграции imports, mappings, errors и metric values.
2. Реализуй private Object Storage и короткоживущие presigned uploads.
3. Проверь MIME, размер и содержимое файла.
4. Реализуй preview с определением UTF-8/Windows-1251 и delimiter.
5. Создай автоматическое и ручное сопоставление колонок.
6. Сохраняй mapping для повторного использования.
7. Реализуй streaming parse и нормализацию дат, decimal и валют.
8. Защити экспортируемые данные от CSV formula injection.
9. Добавь checksum, idempotency и корректную транзакционность.
10. Показывай progress и безопасные ошибки по строкам.
11. Рассчитай базовые агрегаты, но не AI-комментарии.
12. Добавь fixture-based, integration и load smoke tests.

## Ограничения

- Не загружай весь большой CSV в память.
- Float запрещён для денег.
- `null` не заменяется нулём.
- Worker повторно проверяет tenant ownership.
- Не добавляй Excel, Google Sheets и прямые integrations.

## Готово, когда

- все утверждённые fixtures дают ожидаемые totals;
- повторный job не создаёт дубли;
- повреждённые строки имеют исправимые сообщения;
- смешанные валюты не агрегируются;
- типичный файл укладывается в целевое время;
- security tests загрузки проходят.

В финале укажи поддерживаемые форматы, лимиты, результаты fixtures и поведение при сбоях.
