# CSV template v1

Статус: **гипотеза**. Реальных выгрузок в репозитории нет. Владелец обещал обезличенные CSV Директа и/или Метрики; файла Вебмастера не обещал отдельно.

Синтетические примеры:

- [examples/direct_campaign_daily.v1.csv](examples/direct_campaign_daily.v1.csv)
- [examples/metrika_goals_daily.v1.csv](examples/metrika_goals_daily.v1.csv)
- [examples/webmaster_queries_daily.v1.csv](examples/webmaster_queries_daily.v1.csv)
- [examples/webmaster_indexation_daily.v1.csv](examples/webmaster_indexation_daily.v1.csv)

Примеры в Git — UTF-8 с `;`, чтобы их было безопасно хранить. Импортёр MVP обязан принимать Windows-1251 и UTF-8 (решение D-013).

Не класть сюда боевые ключи, логины, URL клиентов, названия юрлиц, телефоны и email из заявок.

## Общие правила импорта

| Правило | Значение |
| --- | --- |
| Периоды | Один файл с колонкой даты; MAG отрезает текущий и прошлый интервал той же длины |
| Строка рекламы | `date` + кампания |
| Строка SEO | `date` + запрос (не кампания) |
| Разделитель | `;` типичный; также `,` и таб, автодетект |
| Десятичные | `,` или `.`; нормализовать |
| Даты | `YYYY-MM-DD` канон; принимать `DD.MM.YYYY` |
| Timezone | дата кабинета без сдвига; хранить timezone клиента |
| Валюта | одна на импорт; иначе блок агрегации |
| Пустой vs ноль | пустая ячейка → `null`; `0` → измеренный ноль |
| Формулы | не исполнять ячейки вида `=...` |
| Лимит | старт 25 МБ, уточнить нагрузкой |

Три источника — три импорта в один отчёт, не один «универсальный» CSV. Канонические поля MAG заполняются маппингом.

## 1. Яндекс Директ — кампания × день

Обязательность: `required` без строки импорт отклоняет; `optional` можно не мапить.

| Поле MAG | Тип | Обяз. | Формат | Пример | Типичные заголовки источника (гипотеза) |
| --- | --- | --- | --- | --- | --- |
| date | date | required | YYYY-MM-DD | 2026-08-01 | Дата, Date |
| campaign_id | string | optional | внешний id | 1110001 | № Кампании, CampaignId |
| campaign_name | string | required если нет id | текст | Услуги \| Поиск | Название кампании |
| source | string | optional | константа `yandex_direct` | yandex_direct | — |
| channel | string | optional | paid_search | paid_search | — |
| impressions | integer ≥ 0 | required | целое | 12000 | Показы |
| clicks | integer ≥ 0 | required | целое | 240 | Клики |
| spend | decimal ≥ 0 | required | 2 знака | 8500.50 | Расход, Cost, Сумма |
| currency | enum | required | RUB / BYN / KZT | RUB | Валюта или настройка клиента |
| conversions | integer ≥ 0 | optional | целое | 6 | Конверсии Директа; **не** замена цели Метрики |

Не использовать conversions Директа как заявки шаблона «услуги», пока mapping клиента явно не скажет иное (D-015).

## 2. Яндекс Метрика — день × источник/кампания × цель

| Поле MAG | Тип | Обяз. | Формат | Пример | Типичные заголовки (гипотеза) |
| --- | --- | --- | --- | --- | --- |
| date | date | required | YYYY-MM-DD | 2026-08-01 | Дата |
| source | string | optional | yandex / organic / direct | yandex | Источник |
| campaign_name | string | optional | текст | Услуги \| Поиск | Last-click campaign, UTM |
| sessions | integer ≥ 0 | required | целое | 210 | Визиты |
| users | integer ≥ 0 | optional | целое | 180 | Пользователи |
| goal_id | string | required | id цели | 123456 | Goal ID |
| goal_name | string | required | текст | Заявка с формы | Название цели |
| goal_completions | integer ≥ 0 | required | целое | 8 | Достижения цели |

`goal_id` — стабильный ключ mapping. `goal_name` может меняться (D-014). В отчёт как «заявки» идёт одна выбранная цель клиента.

Сверка SEO: визиты из поиска считаются отдельным срезом Метрики (`source = organic` или эквивалент). Точное имя среза — `to-validate`.

## 3. Яндекс Вебмастер — запросы

| Поле MAG | Тип | Обяз. | Формат | Пример | Типичные заголовки (гипотеза) |
| --- | --- | --- | --- | --- | --- |
| date | date | required | YYYY-MM-DD | 2026-08-01 | Дата |
| query | string | required | текст запроса | установка кондиционера москва | Запрос |
| page_url | string | optional | URL без PII | https://example.invalid/uslugi | URL |
| impressions | integer ≥ 0 | required | целое | 900 | Показы |
| clicks | integer ≥ 0 | required | целое | 40 | Клики |
| avg_position | decimal ≥ 1 | optional | 1 знак | 4.2 | Ср. позиция |

Не подставлять реальные домены клиентов. В примере — `example.invalid`.

## 4. Яндекс Вебмастер — индексация (если секция включена)

Отдельный файл: в выгрузке запросов обычно нет ошибок индекса.

| Поле MAG | Тип | Обяз. | Формат | Пример |
| --- | --- | --- | --- | --- |
| date | date | required | YYYY-MM-DD | 2026-08-01 |
| pages_in_index | integer ≥ 0 | required | целое | 128 |
| excluded_pages | integer ≥ 0 | optional | целое | 14 |
| error_pages | integer ≥ 0 | optional | целое | 2 |

Состав кодов ошибок Вебмастера — `to-validate`. Пока хранить агрегаты, не сырой лог URL.

## Валидация

Отклонить или пометить ошибкой строку, если:

- пустая `date` или дата вне разумного окна (±5 лет);
- отрицательные показы, клики, расход, визиты, заявки;
- клики > показы при обоих числах не null;
- заявки > визиты при обоих числах не null (предупреждение, не всегда hard fail);
- `avg_position` < 1;
- смешение валют в одном импорте;
- `spend` с валютным символом в ячейке — парсить число, символ сверять с валютой клиента.

Итог импорта: `accepted_count`, `rejected_count`, маскированное значение в ошибке.

## Что проверить по первому реальному файлу

1. Точные заголовки Директа (мастер отчётов vs API-выгрузка).
2. Есть ли в Метрике разрез «день + кампания + цель» или только день + цель.
3. Вебмастер: период агрегации (день или неделя), лимит строк топа запросов.
4. BY/KZT: десятичные и код валюты.
5. Совпадает ли сумма расхода по дням с итогом кабинета.
