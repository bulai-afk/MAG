# Гайд интервью с фрилансерами

Цель: проверить brief на **других** людях, не на владельце продукта. Ответы владельца не засчитываются как рыночные факты.

План: 5–10 интервью. Минимум 5 обезличенных CSV (хотя бы Директ и Метрика). Желательно 3 текущих PDF/презентации без персональных данных.

ICP скрининга совпадает с [PRODUCT_BRIEF.md](PRODUCT_BRIEF.md): соло-маркетолог, РФ/BY/KZ, ежемесячный клиентский отчёт, Яндекс Директ и Метрика. Вебмастер — гипотеза владельца, её нужно отдельно подтвердить.

## Screening

Квалификация (нужны все пункты 1–4):

1. Сам готовит отчёты для платящих клиентов, не только для своего сайта.
2. Не менее одного ежемесячного отчёта за последние 60 дней.
3. Выгружает хотя бы Яндекс Директ или Яндекс Метрику.
4. Отдаёт клиенту файл или ссылку (PDF, презентация, таблица, письмо с цифрами).

Дисквалификация:

- только инхаус одной компании без внешних клиентов;
- агентство, где респондент не собирает отчёт руками (можно отложить в список сегмента 2);
- нет доступа к выгрузкам;
- не говорит по-русски о рабочих цифрах.

Дополнительно зафиксировать, не влияя на отсев:

- число клиентов с регулярным отчётом;
- часы на один отчёт в последний раз;
- есть ли Яндекс Вебмастер в клиентском файле;
- ниша клиентов (услуги / e-commerce / B2B).

Цель скрининга — **не** продать MAG.

## Сценарий (45–60 минут)

Не показывать интерфейс MAG в первых пяти интервью. Не подсказывать KPI из [KPI_DICTIONARY.md](KPI_DICTIONARY.md), пока респондент не назвал свои.

### 1. Контекст (5 мин)

- Чем занимаетесь и сколько клиентов сейчас на регулярном отчёте?
- Кто ещё участвует в сборке и отправке?
- Кто ваш клиент: собственник, маркетолог, закупок нет?

### 2. Последний реальный отчёт (15 мин)

Просить один конкретный месяц, не «обычно».

- С чего начали и чем закончили?
- Из каких кабинетов выгружали? Показать жестами/названиями отчётов, не логинами.
- Куда сводили: Excel, Google Таблицы, Looker, слайды, мессенджер?
- Сколько часов занял **этот** отчёт? Отдельно: выгрузки, формулы, тексты, оформление, правки после клиента.
- Что ушло клиенту: какой файл, какой канал?
- Что клиент спросил или не понял?

Факт: названный час и названный артефакт. Мнение: «клиенты такое любят».

### 3. Боль и обходы (8 мин)

- Где ошибаетесь чаще всего?
- Что уже пробовали вместо ручной сборки и почему бросили?
- Что будет через 6 месяцев, если ничего не менять? Останутся на Excel / упростят отчёт / наймут помощь / поднимут цену?

### 4. Данные (10 мин)

- Можете ли прислать обезличенный CSV за один период? Какие колонки точно есть?
- Два файла периодов или один с датами?
- Есть ли день, кампания, объявление, устройство?
- Кодировка, разделитель, валюта, timezone — если знает.
- Прыгают ли названия целей/кампаний?
- Вебмастер: какие числа **реально** стоят в клиентском PDF? Если ни одного — секция SEO для этого человека не нужна.

Не принимать файлы с телефонами, email заявок, адресами, паспортными данными, токенами.

### 5. KPI и решения клиента (8 мин)

- Какие 5 цифр клиент смотрит всегда?
- Что такое заявка и от чего считаете конверсию?
- Нужны ли выручка, ROAS, ДРР?
- С чем сравниваете период?
- Когда изменение «важное»?
- Какие графики и таблицы клиент правда использует?

### 6. Текст, бренд, доставка (5 мин)

- Кто пишет выводы и сколько минут?
- Можно ли предлагать следующие шаги?
- Чей логотип на файле?
- Файл вручную или нужна ссылка с паролем?

### 7. Цена (5 мин, после описания процесса)

Не называть 3 990 ₽ и не называть $2.

- Если сборка занимала бы 20 минут при том же контроле цифр, что изменится в работе?
- За что разумнее платить: клиенты, отчёты, пользователи?
- Три якоря: «дорого / ещё подумаю / взял бы сразу» — пусть респондент сам назовёт суммы в ₽ за месяц.

Записать готовность дать CSV и согласие на повторный контакт для beta. Имена и рабочие email респондентов — только во внешнем трекере, не в этом репозитории.

## Форма заметок

Копировать на интервью. В Git — только обезличенные агрегаты.

```text
interview_id: F-0X
date:
channel: call / chat / in-person
screener_pass: yes / no
role: freelancer / other
clients_with_monthly_report: N
hours_last_report:
deliverable: pdf / pptx / xlsx / messenger / link
sources_used: direct / metrika / webmaster / other
webmaster_in_client_pdf: yes / no / unknown
assembly_tool:
conversion_definition:
cvr_denominator: clicks / sessions / other
period_comparison_rule:
wtp_month_rub: cheap / think / buy  (суммы)
csv_promised: yes / no
facts:          # только наблюдаемое: часы, файлы, шаги
opinions:       # «должно», «клиенты хотят», оценки без примера
quotes:         # короткие, без имён клиентов
open_questions:
segment_fit: high / medium / low
```

После интервью заполнить одну строку сводной таблицы (вне репозитория или в обезличенном виде):

## Как отличать факты от мнений

| Факт | Мнение / гипотеза |
| --- | --- |
| «Последний отчёт делал 3 часа, выгружал Директ и Метрику, отправил PDF в Telegram» | «Всем клиентам нужен SEO-блок» |
| Показал экран Excel / прислал обезличенный CSV | «Кабинеты никто не понимает» без примера вопросов клиента |
| Назвал сумму, которую платит за другой сервис | «За MAG возьмут 500 ₽» |
| «Цели в Метрике в марте переименовали, формулы сломались» | «Колонки всегда прыгают» |

Правила:

1. Часы — только про последний конкретный отчёт, затем спросить «это типично?».
2. KPI — сначала список респондента, потом сверка со словарём MAG.
3. «Надо три источника» не переносить в MVP, пока 3 из 5 квалифицированных интервью не покажут Вебмастер в **клиентском** артефакте.
4. Готовность к beta = названная дата и тип данных, не «было бы интересно».
5. Не записывать в репозиторий имена клиентов, URL их сайтов, логины кабинетов.

## Квоты выборки

Стремиться не к случайным знакомым, а к разбросу:

- 3 человека с 1–4 клиентами (как владелец);
- 3 с 5–10 клиентами (гипотеза плана);
- хотя бы 2, кто отдаёт PDF, и 2, кто отдаёт таблицу/мессенджер;
- хотя бы 2 без Вебмастера.

Если за 10 контактов не набирается 5 прошедших скрининг — сегмент недоступен, это отдельный go/no-go в [BETA_PLAN.md](BETA_PLAN.md).
