# Спецификация отчёта MVP — шаблон «услуги / заявки»

Версия: 0.1-hypothesis  
Дата: 2026-09-09  
Клиентский артефакт: **PDF**. Веб-ссылка не входит в MVP (D-026, D-027). Предпросмотр в приложении нужен автору, не клиенту.

Секции в **фиксированном порядке**. Скрытие и перестановка — после beta (D-025).

## Секции

| # | id | Что видит клиент | Обязательность |
| --- | --- | --- | --- |
| 1 | cover | Логотип и цвет фрилансера, название клиента (как в карточке MAG), период, дата сборки | всегда |
| 2 | kpi_cards | Расход, заявки, CPL, клики, CTR, CPC, показы, визиты, CVR; Δ к прошлому периоду | всегда |
| 3 | summary | AI-резюме 3–6 предложений, после review автора | всегда; без AI — детерминированный текст из фактов |
| 4 | methodology | Источники, имя и id цели Метрики, правило периода, валюта, timezone | всегда |
| 5 | timeseries | График динамики выбранной метрики: текущий и прошлый период | всегда, если ≥1 точка |
| 6 | funnel | Показы → клики → визиты → заявки | скрыть, если нельзя честно сопоставить визиты |
| 7 | campaigns | График и таблица кампаний Директа | если есть campaign_name/id |
| 8 | seo_queries | Топ запросов Вебмастера | если импорт Вебмастера успешен |
| 9 | seo_reconciliation | Клики Вебмастера vs визиты из поиска Метрики | если оба среза есть |
| 10 | seo_index | Индекс, исключённые, ошибки | если есть indexation CSV |
| 11 | narrative_extra | Достижения, риски, гипотезы, следующие действия | после review |
| 12 | missing_data | Список отсутствующих источников и полей | если что-то не загружено |

Владелец хотел SEO в «первые 30 секунд» (D-021). В PDF это конфликтует с читаемостью KPI услуг: SEO идёт **после** воронки и кампаний. Пересмотр — если usability-тесты потребуют поднять блок.

## KPI-карточки

Словарь: [KPI_DICTIONARY.md](KPI_DICTIONARY.md).

Первый ряд (решение за 30 секунд): `spend`, `leads`, `cpl`.  
Второй ряд: `clicks`, `ctr`, `cpc`.  
Третий ряд: `impressions`, `sessions`, `cvr`.

На карточке: значение, единица, абсолютная и процентная Δ, знак для метрик «меньше — лучше». Цвета бренда не единственный индикатор (D-019).

Нет данных: прочерк и подпись «нет в выгрузке», не ноль.

## Графики

Только те, что выбраны в интервью (D-022, D-023, D-024). Контракт `ChartDataset` — в [`docs/PROJECT_PLAN.md`](../PROJECT_PLAN.md) §6.4; frontend не пересчитывает KPI.

### Динамика

- Тип: line.
- X: день (неделя, если период > 45 дней).
- Две серии: текущий и прошлый; прошлый выравнивается по номеру дня периода.
- Метрики переключателя автора: расход, заявки, клики, визиты, CPL, CTR. В PDF фиксируется метрика по умолчанию: заявки, если есть, иначе расход.
- Одна точка: точка + карточка, не линия.

### Воронка

- Показы → клики → визиты → заявки.
- CVR между этапами.
- Визиты — срез, описанный в методологии. Не смешивать конверсии Директа с целью Метрики.

### Кампании

- Horizontal bar: top 10 по расходу.
- Рядом таблица: кампания, расход, клики, заявки (если сопоставимы), CPL, Δ расхода.
- Без имени: «Без названия» + id.

Не в MVP: каналы grouped bar, 100% stacked расход, график средней позиции.

## Таблицы

1. Кампании — полный список, не только top 10 графика.
2. Топ запросов — до 30 строк: запрос, показы, клики, CTR = clicks/impressions по строке, средняя позиция, Δ позиции. Запросы-примеры в репозитории вымышленные.
3. Сверка: период, клики Вебмастера, organic sessions, ratio.
4. Индексация: дата конца периода и Δ к прошлому интервалу той же длины.

Каждый график дублируется таблицей в PDF (доступность и печать).

## AI-блоки

Вход: агрегаты текущего и прошлого периода, значимые изменения (|Δ| ≥ 10%), top кампаний, top запросов без сырых строк CSV, методология. Без имён людей, телефонов, email, неочищенных URL клиентов.

Выход (после Zod): `summary`, `wins`, `risks`, `hypotheses`, `nextActions`, `referencedFacts`.

Правила:

- цифры только из `referencedFacts`;
- гипотезы не писать как причины;
- 2–3 следующих действия, без гарантий роста;
- тон: спокойный деловой русский;
- автор обязан отредактировать или явно подтвердить перед сборкой PDF;
- если провайдер недоступен — детерминированный список изменений KPI.

## Web и PDF

| Поверхность | Роль в MVP |
| --- | --- |
| Редактор | Автор: импорт, карточки, графики, правка AI, скачать PDF |
| Публичный viewer | Нет |
| PDF | Единственный клиентский артефакт; A4 portrait; графики не рвать между страницами |

PDF строится из того же snapshot, что и предпросмотр. Изменение черновика после сборки не меняет уже скачанный файл, если хранится версия; политика версий — `assumption` (хранить каждую сборку PDF).

## Состояния отсутствующих данных

| Состояние | Поведение |
| --- | --- |
| Нет Директа | Нет расхода/кликов/кампаний; заявки Метрики можно показать; CPL null |
| Нет Метрики | Нет визитов и заявок; воронка обрывается на кликах; SEO-сверка скрыта |
| Нет Вебмастера | Секции 8–10 скрыты с пояснением; отчёт по услугам остаётся валидным |
| Нет прошлого периода | Δ скрыты; AI не сравнивает |
| Неполный период | Баннер «период ещё идёт» |
| mixed-currency | Импорт не агрегируется |
| all-zero | Нулевая шкала и текст |
| Цель Метрики не выбрана | `leads`/`cpl`/`cvr` hidden |
| AI error | Детерминированный текст, PDF можно собрать |

Отсутствие Вебмастера **не** блокирует PDF. Это смягчает риск D-010: владелец требует три источника, продукт должен переживать частичный импорт.
